## Staged-state model

under `next` in dependency order:

1. core `0.4.1`;
2. base Angular `0.4.1`; and

Staging reserves an immutable version but does not make it public. Every stage
must be listed/viewed, downloaded and compared byte-for-byte with the selected
candidate before approval. A pending stage supplies no installation or live
provenance claim.

## Approval and live-state model

Each package requires a separate Ricard 2FA approval in dependency order. After
each approval, verification must observe exact bytes/integrity, registry

- core only leaves base/pilot unpublished and defaults unchanged;
- core/base leaves the pilot unpublished and coordinated completion unclaimed;
- all three exact/`next` versions must pass before any `latest` transition.

After all three exact/`next` lines pass, `latest` may move
deepest-dependent-first: pilot, base Angular, then core. The first two states are
planned mixed windows and provide no accepted coordinated `latest` or
unqualified evidence. Only the final verified alias and consumer matrix may

- `npm stage publish` only, with direct `npm publish` disabled.
