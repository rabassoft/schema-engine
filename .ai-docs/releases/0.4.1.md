## Approval and live-state model

Each package requires a separate Ricard 2FA approval in dependency order. After
each approval, verification must observe exact bytes/integrity, registry
signature, public access, repository metadata and automatic provenance bound to
`rabassoft/schema-engine`, `.github/workflows/npm-publish.yml` and the exact
protected source commit.

Partial publication is truthful but incomplete:

- core only leaves base/pilot unpublished and defaults unchanged;
- core/base leaves the pilot unpublished and coordinated completion unclaimed;
- all three exact/`next` versions must pass before any `latest` transition.

After all three exact/`next` lines pass, `latest` may move
deepest-dependent-first: pilot, base Angular, then core. The first two states are
planned mixed windows and provide no accepted coordinated `latest` or
unqualified evidence. Only the final verified alias and consumer matrix may
close M23.

Each package receives one exact trusted publisher:

- GitHub Actions repository `rabassoft/schema-engine`;
- workflow filename `npm-publish.yml`;
- protected environment `npm-publish`; and
- `npm stage publish` only, with direct `npm publish` disabled.

The workflow uses Node `22.23.1`, exact npm `11.18.0`, pnpm `10.28.2`,
GitHub-hosted execution, no cache or stored release credential, and
`id-token: write` only in the protected staging job. It stages only the three

external use.

Trusted publishing automatically generates provenance for a public package
from a public supported GitHub-hosted workflow. Source preparation does not:
the registry attestation, signature and source binding remain mandatory live
evidence.
